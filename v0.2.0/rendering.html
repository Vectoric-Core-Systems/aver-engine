Voxi is the renderer

The thing that draws Aver's world is Aver.Render.Voxi. It sits at tier 5 of the module graph, alongside the UI renderer and the actor preview, and it owns what most engines would call the render pipeline: anti-aliasing, global illumination, ray tracing, the quality ladder that ties them together, and the feature that walks the draw list and turns it into work.

It was the engine's first pay-for-what-you-use render module, and it still behaves like one. It builds on by default, and the engine builds and runs with -DAVER_MODULE_VOXI=OFF — you get an unshadowed scene with no GI and a status line explaining why, not a broken build.

The name is the honest one. Voxi voxelises the scene and cone-traces through the result, so the voxel grid isn't an implementation detail buried somewhere — it's the thing the module is named after and the thing most of its settings are about.

It names no backend, anywhere

Voxi drives the generic RHI interface and never mentions Direct3D. Its renderer half links Aver.Core, Aver.RHI, Aver.Render.Voxi and Aver.Render.PBR.Materials — and the architecture doc annotates that line with NEVER RHI.D3D12, the same annotation carried by every other tier-5 feature.

That's what makes the backend swappable in principle rather than in a comment. D3D12 is the only implementation that exists today; D3D11 and Vulkan compile and return a null device. But nothing in Voxi would need to change to sit on a different one, because nothing in Voxi knows which one it's on. It asks the RHI what the device can do and works with the answer.

The backend it currently drives owns the device, a DXGI FLIP_DISCARD swap chain with two back buffers, per-buffer fences and window resize. Shaders compile at run time rather than offline: DXC emits DXIL at Shader Model 6.0, stepping to 6.5 for the mesh-shader and inline-RayQuery variants, with an FXC and SM 5.1 fallback that still produces the correct reference image when dxcompiler.dll is missing.

Two targets, and a link line that is the architecture

Voxi is split in half, and the split is the same one Render.PBR uses. Aver.Render.Voxi is SHARED and links Aver.Core and nothing else — it holds the settings and the C seam, so a C# graphics-settings panel can bind it without a single RHI type crossing the P/Invoke boundary. Aver.Render.Voxi.Renderer is STATIC, and it's the half that owns GPU resources.

The renderer half's dependency on Render.PBR.Materials is, as the ABI doc puts it, the architecture written on a link line: Voxi supplies visibility and irradiance and calls the shading model; the material owns the BRDF. The arrow runs that way and never the other.

Which is also why the top-level build forces AVER_MODULE_VOXI off when AVER_MODULE_PBR is off. Voxi renders materials. Without that guard the failure is a C1083 four includes deep, which reads as a broken include path rather than as an invalid module combination — so the build catches it up front and says so.

Voxel cone tracing, which is the whole point

Global illumination works by voxelising the geometry and injecting it into an atomic accumulator by dominant-axis projection. A compute pass resolves that into a 3D radiance volume, another mip-filters it, and the lit pixel shader gathers with six diffuse cones plus ambient occlusion.

It runs at about 59 FPS with a 128³ volume on the reference GPU. The resolution, the intensity and the reach in centimetres are all exposed on the seam, so a settings panel can tune the volume rather than just switching a preset.

Two honest limits. It's diffuse only — specular isn't cone traced — and the volume is rebuilt every frame. There's no temporal accumulation and no cached irradiance sitting between frames.

Ray-traced sun shadows, DXR 1.1 or nothing

Ray tracing in Voxi is inline RayQuery, and only that. Requiring RaytracingTier ≥ 1.1 is deliberate: it excludes GPUs that emulate DXR 1.0 without dedicated RT cores, where the feature would technically run and practically be unusable.

What it traces is exact hard sun shadows, straight from the pixel shader, over a per-mesh BLAS and a per-frame TLAS built from the replayed draw list. With no acceleration structure it falls back to the shadow map rather than failing.

The device's real tier is readable through the seam — 0 for none, 10 for DXR 1.0, 11 for 1.1 — so a settings panel can grey the option out with a reason instead of offering something that will be refused.

Four cascades in one atlas

The shadow map this replaced was a single 2048² texture fitted to the GI volume rather than the camera view. In one test scene that box was forty-four centimetres across, so the arena had no shadows at all. It's now four cascades, each fitted to a slice of the camera frustum and packed 2×2 into one 4096² depth texture — an atlas rather than a texture array, because the RHI has no array-texture concept. The cost is a clamp so PCF taps can't wander into a neighbouring quadrant.

Three details carry most of the quality. Cascades are fitted with bounding spheres, not boxes, because a box changes size as the camera rotates and makes shadow edges crawl, while a sphere only translates. That translation is quantised to whole shadow texels to kill sub-texel crawl. And the bias is normal-offset scaled per cascade, since one constant depth bias can't serve cascades whose texel sizes differ by two orders of magnitude.

The last cascade is unioned with the GI volume, and that's not tidiness. The voxelisation pass samples this same map for every voxel it injects, so a shadowed surface the map doesn't cover will inject sun radiance into the volume and leak light through walls in the bounce. Filtering is 3×3 PCF.

Shading, MSAA and the HDR chain

There's no deferred G-buffer. Full shading is a single forward pixel shader composed from three HLSL fragments: the RHI's shared prelude, the material system's, and Voxi's own. Cook-Torrance GGX, with per-object metallic and roughness arriving as root constants, sky-hemisphere ambient, a sky environment reflection term, sRGB decode going in and ACES plus gamma coming out.

MSAA is a genuine runtime setting rather than a build flag — Off, 2×, 4× or 8×, rebuilding both scene render targets and every pipeline state object on the spot. At one sample it uses CopyResource instead of a resolve, because a D3D12 resolve is illegal at 1×. The seam exposes a support mask, so a panel offers only the counts the device will accept.

The scene renders linear HDR radiance into an RGBA16F target and tonemaps last. Bloom is a half-resolution six-mip pyramid with a Karis-weighted prefilter, a Jimenez 13-tap downsample and a 9-tap tent upsample, added by the fixed-function blender rather than a compute write — which sidesteps a typed-UAV-load hardware dependency. Auto-exposure bins 256 log-luminance buckets at quarter resolution and damps in log space. Every default is the identity, so a feature nobody turned on can't move the oracle.

Sky, clouds and fog

The default sky is a two-colour authored dome, and that default is load-bearing. The gate baseline records 17 probes across 9 device configurations, and a new sky model would move all of them at once and read as a regression everywhere.

So the physical model is opt-in, via --sky-physical or the Sky Model combo in the sun-and-sky Details panel. Turn it on and you get single-scattering Rayleigh, Mie and ozone marched through a spherical shell, plus one flat isotropic term standing in for higher-order bounces. Earth defaults in kilometres: 6360 km planet radius, 60 km air depth, 8 km Rayleigh scale height, Mie anisotropy 0.80 through Cornette-Shanks rather than plain Henyey-Greenstein, and an ozone Chappuis-band tent. Transmittance to the sun is solved analytically with the Chapman function instead of marched, landing within 0.125% of a two-million-step numerical integral.

Only the sky pass marches per pixel. The ambient term, environment reflections, the fog in-scatter target, ground radiance and cloud fill all read a two-colour dome the CPU refits to the current model once per frame — so a physical sky costs nothing extra per surface. Above it sits a single raymarched cloud layer (24 steps, a 3-step light march, Henyey-Greenstein phase, Beer plus a powder term, analytic value noise) and analytic exponential height fog with a closed-form optical depth.

A settings seam that refuses rather than pretends

Voxi's C seam is 21 entry points and the only seam in the engine with no handles at all — a global settings block plus a read-only mirror of what the device reports. Nothing can go stale, so every call is a get or a set with no instance parameter, and the only rejection path is the return value: 1 for accepted, 0 when the request is an unsupported feature or a bad argument.

Features introspect themselves. You can ask how many there are, what each is called, and what state it's in — Ready, NotImplemented or Unsupported — with the status coming from an actual device capability query rather than a guess. A setting refuses to enable rather than accepting the call and quietly doing nothing, which is the failure mode that wastes an afternoon.

The quality-laddered features share one scale (Off, Low, Medium, High, Epic), the GI tunables are separate because a preset isn't always enough, and the capability reads — ray-tracing tier, max MSAA, mesh-shader tier, shader model — are what a panel should be built on. Two const char* returns are the only outbound strings on the whole surface.
