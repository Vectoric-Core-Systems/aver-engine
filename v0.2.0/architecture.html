Architecture

Modular by construction

Tiers, and arrows that only point down

The modules form an acyclic graph seven tiers deep. Aver.Core is at the bottom and knows nothing about the engine above it: maths, logging, time, hashing, types. Aver.Platform sits on Core alone. Then come the device-free subsystem cores — the RHI interface, assets, the retained UI, the audio mixer, physics, materials. Backends and format runtimes above those, gameplay and the C seams above those, the render features that own GPU resources above those, and the editor on top.

Nothing points up a tier. Three edges run sideways within one — Framework → Scene, Audio.Abi → Formats.Audio, Render.Voxi.Renderer → Render.PBR.Materials — and none points backward. Two things keep it that way, and neither is a CI job: a bad edge usually just fails to link, and the edge list in docs/ARCHITECTURE.md gets re-derived from each module's real CMakeLists.txt rather than from the diagram it sits next to.

One rule gets policed separately, because breaking it wouldn't show up at link time at all: no RHI type may cross a P/Invoke boundary. That's why Render.PBR and Render.PBR.Materials are two targets, and why UI and Render.UI are two targets. A C# game binds the settings half without dragging graphics-card types across the managed boundary.

One seam per module, not one flat ABI

The original design had a single interop surface. One extern "C" seam, one aver_abi_version(), everything binding through it. It got designed and then dropped — not postponed. Both modules/abi/ and the top-level abi/ now hold one README explaining the decision, and nothing else.

The problem was that a single seam has to link everything it exposes. That makes three things mutually exclusive: scene_abi.h reading end to end without ever using the word actor, Aver.Render.PBR staying a P/Invoke DLL with no RHI types in it, and one surface changing shape while another is still settling. Those three properties are the reason a seam exists in the first place, so the seam got split instead.

The calling convention survived intact and now repeats across eight DLLs: opaque handles, out-pointer struct returns, POD structs laid out for LayoutKind.Sequential, UTF-8 const char* strings, create and destroy in pairs. Each seam versions independently, which is the whole point — and worth knowing, docs/ABI.md still describes seven of them and 201 exports. There are eight and 225. Audio landed after it was last updated.

No UObject — data, not an inheritance tree

There's no universal base object anywhere. Entities are 32-bit handles, components are plain data in packed arrays, and aver_scene_field() resolves a component field by name at run time rather than through virtual dispatch or generated property code.

Aver.Framework puts the gameplay vocabulary on top of that — game instance, game mode, actors, pawns, possession, begin and end play — as a class registry with defaults rather than a hierarchy you subclass. Spawning an actor copies a row of defaults. That's it.

The docs don't pretend this is free. Looking a field up by name costs more than a compiled offset would. The storage half of the no-UObject idea is enforced by the link lines and holds; the zero-cost-reflection half was never delivered, and ARCHITECTURE.md scores itself accordingly.

The minimum build, and why it matters

Every optional module hides behind an AVER_MODULE_* switch, and turning all of them off still gives you something that configures, compiles, links and runs. That gets checked rather than assumed — each switch has a recorded baseline.

Build with AVER_MODULE_PBR=OFF and the engine still renders, unshadowed and without GI, printing a status line instead of failing. Build with AVER_MODULE_SCRIPTING=OFF and it still starts; --scripts declines politely at run time. Two combinations get caught in CMake rather than deep inside an unrelated header: Voxi renders materials, so it's forced off without PBR, and the framework stands on the scene, so it's forced off without that.

This is what makes the headless suite meaningful instead of decorative. A test executable is added alongside its module, so switching the module off takes its tests with it.

The size of the thing is part of the same argument. The engine is about 49,900 lines of its own C/C++ — 29,300 across the modules, 11,800 in the editor, 8,300 of tests and the rest in tools — plus 7,400 lines of C#. Underneath it sits roughly 182,000 lines of vendored, permissively-licensed code: Jolt, Dear ImGui, stb. Nearly four lines borrowed for every line written, which is the point. The engine is the part that had to be built, not the part that could be linked.

One coordinate contract, settled once

Centimetres. +Z up, +X forward, +Y right. Left-handed. Row-major matrices with row vectors (v * M). Carried over unchanged from OpenConstructor and stated identically in the README and in STATUS.md.

It's a fixed contract, not a setting, and everything is held to it — renderer, physics, formats, scene graph, importers. Jolt works in metres with a different up-axis; that gets translated exactly once, at the physics boundary, and no caller ever sees a metre.

Tests ship with their module, and want no GPU

Each suite is a standalone executable that lands next to Sandbox.exe and runs directly. No test runner, no CTest registration. Which ones exist depends on which modules you compiled.

The renderer-facing suites bring their own mock IDevice, IResourceFactory and IRenderContext, and assert on what got recorded rather than on pixels. That's why the whole suite runs on a machine with no graphics hardware in it.

Pixels get checked separately, by a different mechanism: 17 fixed probe points sampled across 9 device configurations — baseline, no ray tracing, everything off, the mesh-shader path, the WARP software rasteriser, forced Tier-1 caps, the FXC fallback. 153 gates in total, compared as exact 8-bit values against a recorded baseline.

CMakeLists.txt — the guards fire before any add_subdirectory
if(AVER_MODULE_VOXI AND NOT AVER_MODULE_PBR)
  message(STATUS "Aver: Voxi renders materials and cannot be built without them - forcing AVER_MODULE_VOXI=OFF")
  set(AVER_MODULE_VOXI OFF)
endif()

if(AVER_MODULE_FRAMEWORK AND NOT AVER_MODULE_SCENE)
  message(STATUS "Aver: the framework stands on the scene and cannot be built without it - forcing AVER_MODULE_FRAMEWORK=OFF")
  set(AVER_MODULE_FRAMEWORK OFF)
endif()
